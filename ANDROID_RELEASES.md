# Оновлення Android-застосунку

1. Отримайте актуальний код із підключеного репозиторію, встановіть залежності, виконайте `npm run build`, потім `npx cap sync android` перед новою збіркою. Це додає відкриття системного браузера та визначення встановленої версії.
2. У Android Studio залиште той самий `applicationId` і ключ підпису, збільште `versionCode` та вкажіть новий `versionName`. Збережіть ключ підпису окремо та безпечно. Debug-збірки можуть мати інший підпис на іншому комп'ютері.
3. Створіть підписаний APK. Адмінпанель → Налаштування → Мобільний застосунок Android: виберіть файл і внесіть точні versionName/versionCode із збірки. Платформа перевіряє розширення, розмір і заголовок архіву, але не перевіряє сертифікат чи внутрішній versionCode APK.
4. «Опублікувати нову версію» спочатку завантажує новий файл, потім перемикає поточну версію. Старий файл видаляється лише після успішної публікації. При помилці публікації попередня версія лишається доступною.
5. «Оновити застосунок» у нативному Android порівнює номер збірки, показує нову версію й відкриває завантаження в браузері. Старі APK без нових модулів пропонують завантаження без визначення встановленої версії. Android сам запитує згоду на встановлення — сайт не може встановити APK непомітно.
6. У браузері та PWA ця кнопка зберігає попередню поведінку: оновлення вебверсії. Окрема кнопка «Завантажити для Android» працює також на комп'ютері.

Завантаження йде через постійну адресу функції Supabase з короткочасним посиланням на поточний APK. Замість HTML повертається файл `spilnota-bc.apk`. Сам бакет приватний; публікація доступна лише адміністратору.

Фізичне встановлення/оновлення потребує перевірки на телефоні. Якщо Android повідомляє про несумісний підпис, не видаляйте застосунок без резервування даних: зберіть нову версію тим самим ключем. Не обходьте попередження про шкідливий застосунок.

Довідка про Capacitor: https://capacitorjs.com/docs/basics/workflow
